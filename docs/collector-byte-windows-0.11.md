# Controlled first-party receiver-byte windows (experimental)

The optional Chrome + real Egress Guard proxy lab now takes receiver snapshots immediately before and after each sequential synthetic browser action. The existing origin TLS meter counts every decrypted read, including incomplete HTTP requests. Per-connection differences account for reused TCP connections, new connections and reused source ports. Receiver totals must conserve bytes; route evidence, counter monotonicity, error and overflow conditions are checked. No production policy or user browser profile is modified.

For the first-party GA4 query-path case, a narrowly scoped PASS requires a positive receiver-byte delta for each of eight baseline visits, zero new bytes at the same publisher host in every protected sampled window, completed contexts, and the preexisting matcher and functional controls. A positive protected delta, absent baseline, invalid meter, or mismatched denominators cannot earn blocking credit. Such cases are NOT COVERED or fail qualification, rather than being reported as prevented.

**Scope limit:** This measures all application bytes at the controlled receiver during the action interval, not the size of a particular HTTP request. Positive bytes on a shared origin can be unrelated to the action. Traffic delayed beyond the sampled window is not covered. Worker and Service Worker script loading shares the publisher origin, so worker-specific partial-byte prevention is not claimed. The existing dedicated third-party collector-host zero-byte check remains separate and stronger. The existing opaque first-party identifier channel remains admitted and its all-channel matching residual must remain visible.

**Qualification:** Six new isolated Node unit cases cover byte conservation, source-port reuse, zero windows, forged route and corrupt counters, bad host scopes, and baseline/protected thresholding. One new browser contract case covers the first-party gate. Actual Chrome is **NOT COVERED** because this environment previously denied its startup; no retry or bypass was made. The complete repository Python/Node suites for this change and native Chrome execution remain NOT COVERED. Previously reported 0.11 test results do not qualify this later code.
